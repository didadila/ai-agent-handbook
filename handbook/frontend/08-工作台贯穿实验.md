# 工作台贯穿实验：从字节到可恢复状态

这章把前七章连成同一个练习。提供**可直接运行的协议核心与故障测试**，以及浏览器/服务端扩展验收；没有用 Node 测试冒称完整聊天产品已经交付。

## 运行

使用支持内置 `node:test`、TextEncoder/TextDecoder 的现代 Node（建议 Node 20 或更新版本），无第三方依赖。从仓库根目录执行：

```bash
node --test handbook/frontend/examples/workbench-core.test.mjs
```

实现：[workbench-core.mjs](examples/workbench-core.mjs)。测试：[workbench-core.test.mjs](examples/workbench-core.test.mjs)。先自己根据题目设计断言，再看参考实现，避免把参考代码的行为当唯一正确答案。

完整代码验证还包含[语言机制例子](examples/knowledge-examples.test.mjs)，执行 `node --test handbook/frontend/examples/*.test.mjs`。本轮范围与结果见[知识校验和评测](../../docs/reports/2026-11-09-frontend-evaluation.md)。

## 固定契约

- run_id 标识一次任务；seq 是该任务连续递增的正整数；初始投影 last_seq=0。
- 示例只支持 data-only SSE：UTF-8、LF/CRLF/CR 分行、空行结束、多行 data、注释与有界帧。它不是完整 EventSource 实现，不维护 event/id/retry；游标来自 JSON seq，重连网络与HTTP状态处理交给调用层。
- 事件只实现 text.delta、approval.required、run.completed/failed/cancelled 的投影。工具卡片、业务命令、queued/start/resume 全状态机是后续 UI/服务端练习。
- 校验在应用前执行；外部坏数据、未知版本/事件进入明确错误。跨 run 事件不修改当前投影；重复 seq 忽略；缺口拒绝，调用层必须补历史或快照。
- 一次 apply 返回同时更新的正文、任务状态、审批信息与游标；持久化时保存整个投影。本地缓存不可信，restore 校验形状；真正权威快照来自已鉴权服务端。
- cancel_requested 是独立布尔字段，只表达本地意图，不覆盖 status 中最后已知的服务端任务状态；完成事件可能先于实际取消提交，允许最终 completed。终态清除待处理意图。示例绝不执行退款或文件删除。
- 非法UTF-8在本实验中采用严格拒绝策略；这不是原生EventSource规范中错误解码行为的完整复刻。任何解析/校验错误后由调用层销毁该解析实例，基于最后已完整应用的游标恢复。

## 按章推进

| 阶段 | 学习任务 | 本仓库可运行证据 | 延伸到产品后的验收 |
|---|---|---|---|
| 1 基础 | 找出共享对象与异步顺序；用unknown校验输入 | 非法payload/版本拒绝 | 输入框/按钮语义、长内容布局 |
| 2 状态 | 旧scope拒绝提交，恢复投影 | 可控旧请求晚返回、快照往返 | 切会话、刷新、Strict Mode无双订阅 |
| 3 流 | 分片解码、重放、缺口、EOF | 所有二段字节切点、逐字节、重复与断帧 | 代理缓冲、断线重连、401、游标过期 |
| 4 审批 | 投影waiting_approval，取消意图不是终态 | 审批快照、取消/完成竞争 | 服务端拒绝参数变化、过期、重复批准 |
| 5 工件 | 区分可显示文本与可执行内容 | 核心只有纯文本，没有DOM执行能力 | Markdown攻击、sandbox出口、If-Match冲突保留草稿 |
| 6 体验 | 在生成时仍可操作与感知状态 | Node不测布局/读屏/性能 | 长会话输入延迟、键盘审批、焦点返回、放大 |
| 7 交付 | 确定性的协议不变量可重复验证 | 直接跑故障测试 | 旧chunk/协议兼容、灰度、回滚 |

## 浏览器工作台验收矩阵

以下是实现界面时的独立期望，**不是已运行通过的结果**。故障模拟器应控制时钟、分片、服务端状态与响应顺序。

| 故障输入 | 应观察到的结果 | 主要知识点 |
|---|---|---|
| A请求晚于B完成 | B会话内容不被覆盖 | lifecycle |
| 消息stream重复seq | 原消息不重复，游标不倒退 | stream |
| seq缺口且历史过期 | 拉带游标快照后续流，不静默漏字 | stream/state |
| 意外EOF无终态 | 显示连接失效/恢复中，任务不标完成 | state |
| 取消请求超时，随后完成 | 展示真实终态，不能声称已回滚 | approval/async |
| 审批参数或对象版本改变 | 服务端拒旧批准；UI刷新后重新确认 | approval |
| 确认按钮连续点击 | 服务端最多一次业务效果 | approval/http |
| 恶意Markdown/外部资源 | 无脚本执行，无未授权外发 | security |
| OCR排队 | 显示处理中，不以上传完成冒充可检索 | artifact |
| 保存遇版本冲突 | 保留本地dirty内容，明确冲突 | artifact |
| 用户上滚时持续输出 | 保持阅读位置，可手动回到底部 | performance |
| 键盘打开/关闭审批 | 焦点可预测，状态不逐token轰炸 | a11y |
| 老标签页加载懒chunk | 旧资源存在或给出可恢复升级路径 | delivery |

合格的工程作业需要分别提交浏览器轨迹、服务端业务效果和可复现输入。只提交一张成功截图不算完成这些验收。
