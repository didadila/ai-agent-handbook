# 第 7 章 测试与交付

依赖：前六章。发布时要同时保护任务状态、数据安全、交互能力与新旧客户端兼容。

## fe.quality.delivery —— 发布的是一组兼容的资源

### 结论

锁定依赖与工具链、版本化静态资源、约定协议兼容窗口，才能使发布与回滚可重复。

### 案例

HTML 引用新 chunk，但 CDN 仍缓存旧入口；用户打开旧标签页后点“查看引用”，动态导入的旧 chunk 已被删除，页面白屏。只回滚最新 JS，服务端已不再接受旧审批协议，回滚后仍无法操作。

### 机制

| 环节 | 要保护的关系 |
|---|---|
| 安装 | package 与 lock 一致；固定 Node/包管理器与关键配置，使用可重复安装流程 |
| 构建 | ESM 导入与副作用声明正确；动态加载边界考虑初始包与后续网络瀑布 |
| 资源 | 带内容哈希的资产可长期缓存；入口短缓存/重新验证，保留兼容窗口内旧 chunk |
| 配置 | 浏览器 bundle 中的配置不是秘密；服务端凭据不能以“环境变量”名义打包进去 |
| 协议 | 已知事件向后兼容；无法理解的版本进入明确升级路径，不擅自当成功 |
| 灰度 | 关联客户端 build、协议版本和 trace；按用户旅程观察失败再放量 |
| 回滚 | 同时保留旧资产与服务端兼容窗口；破坏性数据迁移须有单独策略 |

`npm ci` 要求已有 lock，依赖声明与 lock 不一致时退出，避免 CI 静默改锁；它不保证所有工具链和外部下载都可复现。选用其他包管理器时核对其 frozen-lock 等价行为。[npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/)、[HTTP 缓存](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)

### 误解靶子

“有 lock 就能永远复现。”“前端回滚只要改入口文件。”“VITE_ 开头的变量就是秘密。”它们忽略环境、资源引用和客户端可见性。

### 判据

一个发布前已打开的旧标签页，在新服务端和新静态资源上线后，能否完成任务或进入明确恢复路径？

### 自测题

1. 旧标签页动态导入旧 chunk 404，只指定发布体系应保留的资源。
2. 服务端凭据进入 bundle，只指出其保密边界是否仍成立。

## fe.eval.journey —— 测用户行为与状态不变量

### 结论

按风险把纯逻辑、协议与浏览器旅程分别验证；截图或函数测试不能替代跨层故障验收。

### 案例

CI 的 reducer 测试全绿，浏览器中真正的停止按钮却在窄屏被覆盖。端到端测试又只等出现“完成”文字：连接意外关闭时 UI 误报完成，测试反而放行。

### 机制

| 层 | 验证内容 | 证据 |
|---|---|---|
| 纯逻辑 | 事件校验、去重、顺序、终态、过期 scope | 确定输入与独立期望状态 |
| 传输契约 | 任意字节分片、EOF、快照与续流、401/游标过期 | 可控服务端序列与协议日志 |
| 浏览器 | 真正点击/键盘、导航、滚动、焦点、窄屏、安全渲染 | DOM 可观察结果与网络请求 |
| 服务端安全 | 审批篡改、越权、重复提交、执行前状态变化 | 服务端拒绝与唯一业务效果 |
| 线上 | build/trace 关联、旅程成功、尾延迟、错误分类 | 实际流量指标与脱敏事件 |

测试期望来自契约，不从系统自己的轨迹反推“做了什么就该允许什么”。用受控时钟/延迟制造乱序，避免固定 sleep；优先按角色、标签等用户可见含义定位。对 retry 通过保留 flaky 证据，不把重跑掩盖的失败当确定可靠。对随机模型多次评测，确定性的流恢复则要求相同输入得到一致状态。[Playwright 测试原则](https://playwright.dev/docs/best-practices)、[Agent 断言与回归](../ai-agent/06-评估.md)

本仓库提供的 Node 协议实验只覆盖纯逻辑与字节分片，不启动浏览器、不证明 DOM 清洗或真实服务端授权。把未运行的层写成验收清单，不写成“全链路测试已通过”。

### 误解靶子

“快照更新后测试就修好了。”“看到了完成文字就能上线。”“前端单测拒绝越权证明后端也拒绝。”期望来源与实际执行层必须独立。

### 判据

每一项可能造成串会话、漏事件、重复执行或错误授权的故障，是否有独立输入、期望与对应层证据？

### 自测题

1. 只为“意外 EOF 不得标完成”写一条可执行期望。
2. 真实按钮被遮挡，只选择能验证该失败的测试层。
