# 第 5 章 输出与工件安全

依赖：HTML/事件语义、TS 边界、HTTP 权限与审批。本章分别保护浏览器执行环境和用户正在编辑的工件。

## fe.security.output —— 模型输出到 DOM 是新的信任边界

### 结论

模型输出、工具结果和上传预览都按不可信内容处理；每个可执行入口必须建立与其上下文相符的限制。

### 案例

工具返回 Markdown 链接，URL 使用危险协议。页面只清理了 `<script>`，最终 Markdown 转 HTML 时仍生成可点击的危险链接。另一次答案插入远程图片，将敏感标识带到外部请求。

### 机制

| 渲染入口 | 本书处理方式 |
|---|---|
| 普通文本 | 用文本节点/框架正常文本插值，不拼 HTML |
| Markdown | 明确关闭或清洗原生 HTML；在最终插入前执行维护中的 allowlist sanitizer |
| 链接与图片 | 解析 URL 后限制协议、来源与资源类型；外部加载按数据外发策略处理 |
| 代码块 | 显示为代码，不因语言标注自动 eval；复制和运行分别授权 |
| 可执行工件 | 独立来源与最小 sandbox 能力；限制网络、导航、下载等出口 |
| 跨窗口消息 | 校验 `origin`、`source` 与消息 schema，不接受任意窗口指令 |

HTML、属性、URL、脚本上下文的编码规则不同。“清掉 script”不等于覆盖事件属性、危险 URL 与 DOM 注入。CSP 是纵深防护，不能代替安全的 DOM API 和清洗；给不可信 iframe 同时开放脚本与同源权限可能削弱隔离，须结合 origin 和能力设计验证。样式与远程资源也可能造成欺骗或外发，不能只检查 JS。[OWASP XSS 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)、[iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)

XSS 让浏览器执行攻击内容，提示注入让模型改变决策。安全展示不能替代工具侧权限；模型拒绝恶意内容也不能代替 DOM 清洗。两条链分别验收。

### 误解靶子

“React 默认转义，所以 `dangerouslySetInnerHTML` 也安全。”“模型说内容安全就可以预览。”它们都跳过了实际执行入口。

### 判据

任意工具返回能否通过链接、资源、脚本或跨窗口消息跨越预定权限边界？

### 自测题

1. 为“Markdown 中的危险协议 URL”指定一个拒绝位置。
2. 只判断工具执行权限校验是否能替代 HTML 清洗。

## fe.product.artifact —— 工件要保留身份、版本与所有权

### 结论

工件是带版本的业务对象；上传成功、处理完成、用户编辑和模型产物不能合并成一个“文件已就绪”。

### 案例

用户上传 PDF，界面马上显示“可以引用”，实际 OCR 仍排队。随后用户改了一段草稿，Agent 的旧自动保存请求返回，把新内容整段覆盖。点击引用又跳到最新文档的错误页码。

### 机制

| 边界 | 必须保留的信息 |
|---|---|
| 上传 → 可用 | upload_id、大小/类型限制、传输进度；服务端检查与处理状态独立 |
| 文档 → 引用 | document_id + version + 稳定位置；原文件变化后不悄悄指向新内容 |
| 草稿 → 保存 | 基线版本与本地 dirty revision；冲突保留用户输入，明确合并或重新加载 |
| 多模态 → 任务 | uploading/processing/ready/failed 等阶段，缺失内容不伪装成功 |
| 会话 → 资源 | 上传取消、对象 URL 回收、预览销毁；不可把前一租户的本地缓存复用给下一租户 |

`accept` 与客户端 MIME 检查只改善体验，服务端仍需验证文件、限制大小与权限、隔离存储和预览。资源 URL 不代替对象授权。条件更新可用 ETag/If-Match 实现版本前置条件，冲突时保留草稿并显示差异，不自动覆盖；正文合并涉及领域语义，不能只按时间戳判谁新。[上传安全](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)、[If-Match](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/If-Match)、[对象 URL 回收](https://developer.mozilla.org/en-US/docs/Web/API/URL/revokeObjectURL_static)

### 误解靶子

“上传 HTTP 200 等于知识已入库。”“最后返回的保存请求就是最新内容。”“引用带个链接就算可追溯。”这些都丢失了阶段或版本维度。

### 判据

一个旧版本保存响应能否覆盖较新的本地编辑，或把引用改指向另一版证据？

### 自测题

1. 基于 v3 的保存遇到服务端 v4，只选择一个保留用户数据的结果。
2. 只列出引用对象中防止版本漂移所需的版本字段。
