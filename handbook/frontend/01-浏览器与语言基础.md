# 第 1 章 浏览器与语言基础

本章 7 点是后续状态、流式交互和安全的前提。贯穿案例是一个 Agent 工作台：左侧会话列表，中间消息流，右侧工具与审批卡片。案例均为教学构造，数字不是线上统计。

## fe.web.semantic —— 元素也是交互契约

### 结论

先选择表达动作、导航和输入关系的原生元素，再添加样式；视觉上像按钮不等于能被当作按钮操作。

### 案例

“停止生成”用 `<div onclick>` 实现。鼠标能点，但键盘用户按 Tab 找不到它，自动化测试也只能按 CSS 类名点击。右侧审批弹窗关闭后焦点丢失，用户不知道当前位于哪里。

### 机制

DOM 表达文档和控件结构，浏览器还会据此构造可访问性信息。`button`、`a`、`label` 分别提供动作、导航、输入关联等语义。给 div 设置 role 不会自动补齐键盘事件、焦点和禁用行为。原生按钮置于表单内时还需明确 `type="button"`，避免意外提交。事件可冒泡，委托监听器要区分 `target` 与 `currentTarget`，避免点卡片内链接却触发整卡审批。

```html
<label for="prompt">任务描述</label>
<textarea id="prompt" name="prompt"></textarea>
<button type="button" aria-label="停止当前任务">停止</button>
```

语义正确让键盘、读屏和基于角色的测试共享同一套界面含义。[键盘可访问性](https://developer.mozilla.org/en-US/docs/Web/Accessibility/Guides/Understanding_WCAG/Keyboard)

### 误解靶子

“加一个 `tabindex` 就与 button 等价。”它只改变聚焦能力，不补齐完整交互契约。

### 判据

不使用鼠标，能否定位并触发停止动作，且触发后焦点仍处于合理位置？

### 自测题

1. 只给一个鼠标可点的审批控件选择合适的 HTML 元素。
2. 卡片内链接点击后触发了父级审批，指出应检查的一个事件边界。

## fe.css.layout —— 布局由约束求解

### 结论

排查布局先查尺寸约束、盒模型和内容最小尺寸，不能把“Flex 已经设置”当作不会溢出的保证。

### 案例

工作台在桌面正常；窄屏显示一条没有空格的工具日志后，中间列撑破容器，输入框被挤出屏幕。反复改 `width: 100%` 没有效果。

### 机制

盒子的内容尺寸、padding、border 共同决定占用；`border-box` 将后两者计入声明宽高。Flex/Grid 子项的自动最小尺寸可能受内容影响。允许中间列收缩通常需要 `min-width: 0`；Grid 可用 `minmax(0, 1fr)` 表达允许收缩的轨道。代码块自身设置滚动边界，而非让整个页面横向滚动。纵向布局也需检查 `min-height` 与可确定的容器高度。

```css
.workspace { display: grid; grid-template-columns: 16rem minmax(0, 1fr); }
.conversation { min-width: 0; }
.tool-output { max-width: 100%; overflow: auto; }
@media (max-width: 48rem) { .workspace { grid-template-columns: 1fr; } }
```

级联按来源、重要性、层、选择器等规则决定最终值；样式没生效先看 computed styles。响应式要覆盖窄屏、放大和内容变长，不只对齐设计稿宽度。[盒模型](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics/Box_model)、[Flex 子项最小尺寸](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/min-width)

### 误解靶子

“`overflow: hidden` 修好了。”它可能只是把内容与焦点环裁掉，未解决收缩或内容可访问问题。

### 判据

最窄支持视口与放大状态下，长日志是否在指定容器内滚动，主要操作是否仍可达？

### 自测题

1. 只指出导致一个 Flex 子项拒绝收缩的候选约束。
2. 给长代码行选择一个保持可读性的溢出策略。

## fe.web.rendering —— 改 DOM 后还有渲染工作

### 结论

JS 执行完不等于用户已看到变化；样式计算、布局、绘制和合成都可能占用交互时间。

### 案例

每个 token 到达就追加文字、读一次 `offsetHeight`、再改滚动位置。模型输出很快，但输入框明显卡顿。开发者只统计 fetch 耗时，因此误以为前端没有瓶颈。

### 机制

HTML/CSS 形成文档与样式结构，再生成布局和像素。DOM 或样式写入之后立刻读取依赖几何的数据，可能迫使浏览器同步完成待处理布局；循环交错读写可反复付费。先集中读取，再集中写入，减少强制布局。资源发现、脚本执行和 CSS 也影响首屏；性能排查要从用户动作到下一次绘制看完整链路。[关键渲染路径](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Critical_rendering_path)、[布局抖动](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing)

### 误解靶子

“把代码放进 `requestAnimationFrame` 就不会卡。”回调中的重活仍会阻塞该帧；调度时机不是计算预算。

### 判据

一次可复现的卡顿在性能轨迹中主要耗在 JS、样式、布局还是绘制？

### 自测题

1. 给“写 DOM 后立刻读尺寸”的循环指定一处应合并的边界。
2. 只解释为什么 fetch 很快不能证明界面很快。

## fe.js.value —— 拷贝对象不等于复制整棵数据

### 结论

对象展开只复制一层属性；更新嵌套状态时必须明确哪些对象仍被共享。

### 案例

```js
const saved = { message: { text: '旧答案' } };
const draft = { ...saved };
draft.message.text = '新答案';
```

用户撤销编辑却发现“原始答案”也变了，因为 `saved.message` 和 `draft.message` 指向同一对象。

### 机制

JS 变量存放值，对象值使多个绑定能引用同一对象。`const` 限制重新赋值，不会冻结对象；`===` 对对象比较身份。数组和对象展开是浅拷贝，原型链查找也不等于自有属性。更新上述状态需要沿修改路径创建新对象：`{...saved, message: {...saved.message, text: '新答案'}}`。深拷贝不是通用替代：函数、DOM 节点、循环引用与特殊类型各有语义，JSON 往返也可能丢数据。[展开语法](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Spread_syntax)

### 误解靶子

“用了 spread 就完全独立。”“const 对象不会变。”两者都没有建立嵌套对象隔离。

### 判据

修改路径上的哪一级对象仍与历史快照相同？

### 自测题

1. 写出上例执行后 `saved.message.text` 的值。
2. 只补出隔离 `message` 更新所需的表达式。

## fe.js.scope —— 回调保留的是词法环境

### 结论

闭包让回调保留定义处的绑定；要区分共享的可变绑定和每轮独立的局部绑定。

### 案例

```js
const jobs = [];
for (var i = 0; i < 3; i++) jobs.push(() => i);
console.log(jobs.map(run => run()));
```

三个工具卡片本应分别定位各自下标，却都得到 3。

### 机制

闭包关联函数与词法环境；`var` 循环共用一个绑定，循环结束后它的值已变成 3；`let` 循环可为每轮建立独立绑定。闭包不是总会冻结值：捕获可变对象后读取其属性，仍可能看到修改。普通函数的 `this` 取决于调用方式，箭头函数沿用外层 `this`；把方法直接当回调传递时需核对接收者。ES 模块把共享状态放进模块作用域，仍不等于按会话隔离。[闭包](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Closures)

### 误解靶子

“回调一定拿最新值。”它能读什么取决于捕获的绑定和该绑定是否还变化；React 每轮渲染又会建立自己的绑定。

### 判据

这个异步回调读的是哪个作用域的绑定，后续更新修改的是否还是同一个绑定？

### 自测题

1. 只预测上例打印的数组。
2. 将 `var` 换成 `let` 后，只解释绑定数量的变化。

## fe.js.async —— 等待结束与工作结束是两件事

### 结论

Promise 表达异步结果；超时、拒绝或停止等待不会自动撤销已经启动的工作。

### 案例

```js
console.log('A');
setTimeout(() => console.log('T'), 0);
Promise.resolve().then(() => console.log('P'));
console.log('B');
```

另一个问题更危险：外层退款 Promise 超时，底层请求继续提交，前端又发送了新退款。

### 机制

在这里给定的浏览器普通脚本环境中，同步代码先执行，Promise 回调在微任务检查点运行，timer 后续成为任务，因此顺序是 A、B、P、T。连续追加微任务也可能延迟渲染。`Promise.all` 快速拒绝不取消其他输入；`Promise.race` 只决定外层结果。AbortController 向支持 signal 的 API 发出取消信号；它无法保证服务器已撤回副作用。timer 是最早调度条件，不保证准时执行。[执行模型](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Execution_model)、[AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController)

### 误解靶子

“`await` 后面的工作天然不会并发。”“`race` 超时等于请求取消。”调用时机与底层 API 契约才决定这些性质。

### 判据

外层结束后，底层操作能否继续完成并产生副作用？

### 自测题

1. 只写出代码的日志顺序。
2. 只指出退款超时后能够安全重试所需的一项服务端保证。

## fe.ts.contract —— 类型在边界之后才可信

### 结论

TS 静态检查不验证网络数据；外部输入先做运行时校验，再进入受类型保护的内部流程。

### 案例

接口升级后把 `seq` 改成字符串，客户端仍写 `JSON.parse(raw) as RunEvent`。编译通过，排序出现 `"10" < "2"` 的字典序问题。`as` 没有修复输入。

### 机制

将外部数据视为 `unknown`，检查对象形状、字段类型、取值范围与版本，再转换为领域类型。用 `type` 字段的可辨识联合表达互斥事件，而非所有字段 optional；穷尽分支检查提醒新增变体，但它覆盖的是已知类型，不是未来服务端输入。泛型能保留输入输出关系，不能自动验证 JSON。schema 通过仍需检查 run、租户、对象权限等语义。[TS 类型断言](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html)、[联合与收窄](https://www.typescriptlang.org/docs/handbook/2/narrowing.html)

```ts
type RunEvent =
  | { type: 'text.delta'; text: string }
  | { type: 'run.completed' };
// 网络入口：decode(raw: unknown) -> 校验成功的 RunEvent 或明确错误
```

### 误解靶子

“接口类型由后端生成，所以前端不用校验。”旧客户端、代理、迁移期数据和错误响应都可能不符合当前类型。

### 判据

未知事件或非法字段在进入 reducer 前，由哪一段可执行代码拒绝或进入兼容分支？

### 自测题

1. 只指出 `as RunEvent` 无法完成的边界工作。
2. 为未知事件选一个不会假装成功的处理结果。
