# 增量工程练习：从局部函数到 Agent 链路

更新：2026-11-09。补充原 29 点小册与技能图谱之间的工程练习，不更改已有 ID 或学习档位。题目为原创迁移，不复制社区题解。

## 限时不等于取消

**结论**：外层 Promise 超时拒绝，不代表内部工作已停止。

案例：退款工具在 100ms 返回超时，500ms 后实际扣款；外层立即重试造成第二笔扣款。

机制：比赛式等待只决定外层结果；实际中止需底层响应取消信号，已提交的副作用还需幂等与状态查询。对应 `agent.tool.sideeffect`、`agent.runtime.durable`。

误解靶子：给所有工具加一个超时包装就能安全重试。

判据：超时后的原始操作还可能提交吗？没有服务端证据就保留未知状态。

自测：画出外层超时后内部操作仍完成的时间线。

练习入口：[力扣 2637](https://leetcode.cn/problems/promise-time-limit/)，本轮核验题目要求是限时 resolve/reject，不包含副作用取消保证。

## 缓存到期不等于记忆失效

**结论**：TTL 只解决时间淘汰，授权撤销、事实覆盖与租户隔离还需额外机制。

案例：旧定时器把刚覆盖的同 key 新值删掉；另一个风险是租户 A 命中了租户 B 的检索缓存。

机制：覆盖时清理旧计时器或使用代际标识；读取时检查到期时间。业务缓存键还应含主体/租户、权限与数据版本等必要维度，权限变化时重新授权或主动失效。对应 `agent.ctx.memory`、`agent.safety.boundary`。

误解靶子：设置短 TTL 就不可能泄漏旧权限数据。

判据：同一个 key 被覆盖后，旧清理任务能否删除新代数据？

自测：设计一个能触发旧计时器误删新值的调用序列。

练习入口：[力扣 2622](https://leetcode.cn/problems/cache-with-time-limit/)，题内的整数键缓存不验证上述业务隔离。

## 防抖不等于消除竞态

**结论**：防抖控制启动频率；已发出的请求仍可能乱序返回。

案例：先发 A 再发 B，B 先返回，随后 A 覆盖当前检索结果。

机制：请求绑定 query revision；只有匹配当前 revision 的结果能提交 UI 状态。取消可减少浪费，版本比较用于拒绝过期提交；组件卸载还需清理定时器和订阅。

误解靶子：输入框加 debounce 就不会显示旧答案。

判据：结果提交时是否仍属于当前会话与查询版本？

自测：为 A/B 逆序完成写一条期望断言。

练习入口：[力扣 2627](https://leetcode.cn/problems/debounce/)；生命周期与乱序处理参考 [React useEffect](https://react.dev/reference/react/useEffect)。

## 联合验收

实现一个最小检索聊天页：查询防抖、请求版本隔离、流事件去重、明确的未知/失败/完成状态。用可控延迟模拟乱序、断线、超时、重复事件与卸载。每个故障单独给出输入序列和期望状态；函数题 AC 只验证局部契约，不能代替这组验收。
