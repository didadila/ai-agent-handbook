# 简历声明与出题

## 解析为可核实声明

为相关声明分配 C1、C2 等 ID，保留原文摘录或文件章节。区分“用户声明”“用户澄清”“本轮已验证”，不把简历内容当能力事实。

| 内容 | 提取 | 不推断 |
|---|---|---|
| 技能 | 明确列出的技术与版本 | 写了 Redis 不等于懂所有数据结构 |
| 项目 | 场景、职责、决策、协作边界 | “主导”不自动等于架构能力强 |
| 成果 | 数值、基线、统计口径、时间范围 | 缺口径不等于造假，也不补造数字 |
| 经历 | 与岗位相关的职责和问题复杂度 | 不从年限直接确定能力等级 |

岗位矩阵包含：要求 ID、能力、是否必需、预期表现、关联声明、计划验证方式、当前证据。JD 要求简历没写的，也需要考察。缺 JD 时明确标注假设。

## 追问链示例（供面试官使用，不提前展示）

声明 C1：“通过缓存将接口 P99 降低 40%”。

1. 首题：这次优化中你个人负责了哪部分？
2. 从回答选择一个缺口：40% 是在怎样的测试口径下得到的？
3. 机制：这条请求从进入服务到返回，缓存在哪一步发挥作用？
4. 边界或迁移：如果缓存中的数据比数据库旧，当前方案会产生什么业务后果？

这些是候选问题，逐次选择，不一次发完。用户若已解释测量，就不重复问口径；用户做的是前端优化，就不能强套 Redis 场景。

个人贡献说不清时，中性询问其亲自做出的决策；不能替其写出“主导了……”的故事。保密数据可接受合理范围、相对量级与测量方法，不逼迫披露雇主机密。
