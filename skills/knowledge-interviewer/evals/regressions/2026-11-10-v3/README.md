# v3结构、权限与准确性定向回归

## 协议

先写16个cases及rubric，再逐例启动独立冷启动执行体。只给候选Skill路径、原话、合成夹具、日期和允许的文件边界；不给rubric、旧结果、真实档案或个人偏好。四域format各1例、四域0755权限拒绝各1例，另有只读竞争反例、正常网络重复副作用、带数字换点、前端普通wrong/skip、Agent route、Java版本boundary及独立私有目录成功保存各1例。

原v1/v2共24份运行文件、4份rubric和4份cases.json共32份文件的SHA256冻结在baseline-sha256.json。域内旧rubric与24/24结果不改，新标准不能回溯重评旧分数。

## 结果

16/16例、79/79条预声明判据满足。四域补课和五个收尾均通过v3固定标题及段内元素粗检；四个拒绝目录保持0755且0个文件；成功路径根/领域/sessions为0700，所有新档案文件0600。sandbox-observations.json保存真实沙箱模式、文件清单及合成正文；不含真实学习档案。

responses.json是实际完整输出、命令与读取路径，grades.json是逐条评审。结构由check_response_format.py独立计算，check_fix_regressions.py会拒绝“结构检查失败却判该条通过”的归档矛盾，仍允许忠实保留失败输出。

候选评测通过后，按用户授权将Qoder全局软链指向当前仓库，旧工作副本未改。随后两个全新执行体只拿全局入口完成补课与路由冒烟，结果在[global-entry](global-entry/README.md)，不与这16例合并报分。

## 限制

每例n=1、执行与评审同族模型；本轮不是原24例按v3标准全量重跑，不是稳定性、人类验证或真实浏览器验证。格式粗检只验证结构和内部标识外露，不能证明机制正确、数字真实或语义动作数。

全局入口校验只覆盖文件身份、主Skill/配套资源与冷启动读取；没有检查Qoder已打开会话的缓存或实际宿主进程。个人偏好被测试边界禁止读取，因此本轮没有验证个性化偏好的实际执行。

环境路径归档时替换为<REPO>、<GLOBAL_SKILL>、<SANDBOX>、必要时<HOME>；正文与工具结果不删改。部分表格仍使用类比，未提供个人偏好且预声明rubric未禁止，未事后增设扣分项。
