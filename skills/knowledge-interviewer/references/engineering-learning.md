# Agent 工程闭环的陪练协议

## 入口与范围

用户学习评测运营、跨上下文长任务或记忆分层时按需读本文件，再用 `learning_content.py` 定位已有知识点正文。它扩展既有机制，不新增学习者成绩字段，不把某篇研究的架构命名变成所有系统必需的标准。

| 判断对象 | 领域与正文 |
|---|---|
| 语言无关的评测协议、上下文交接、记忆派生 | `ai-agent`；第2、5、6、7、9章 |
| Python runner、数据库、worker 与测试实现 | `python-backend`；第6章，并选读通用卷 |
| 五天初学路线 | 仍按 `sprint-learning.md`；下面的进阶内容不自动增加必学清单 |

先确定当前用户要计划、短补课、单题诊断还是实际改动，保持每轮一个作答动作。用户明确要先讲时直接讲；不能把三块主题一起变成考试。

## 评测运营

把四件事分开：开发集用于修改被测系统；保留集用于尚未参与调优的检验；人工校准集用于检验裁判；独立的裁判保留样本用于验证裁判调优后的效果。按意图族/近重复组隔离，改写文字不自动产生独立样本。保留结果一旦指导修改，就记录暴露并更换后续未使用样本，不再称其 untouched holdout。

单次运行是该次观察的有限证据，不能证明稳定性或普遍改进。按 case 配对比较并保留每次通过/失败、错误代价和环境信息；不丢弃 flaky 的失败次数。70%到85%的观测极差是15个百分点，不是“±15”、置信区间或永久噪声门槛。

人工一致率必须连同样本量、标签分布、逐判据混淆矩阵和误放行/误拒绝成本解释；52%不能不加条件地等同抛硬币。人工分歧先复核标准；交换顺序、拆细 rubric 可减偏差，不能保证消除。同模型家族、独立上下文的裁判仍不是人工校准或客观真值。

CLI与SDK结果仅在工具集、身份权限、提示/模型、重试/解析、会话和环境契约对齐后才可比较。同一工具名称不证明同一能力。确定性检查可复验，不等于 oracle 无误；未随正常改动翻转的断言仍可守护不变量。受控 mutation 只检验针对所注入故障的检测能力。

本仓库历史 Python 六例评测是开发期合成回归：新版21/22判据、5/6用例，每配置每例一次，同族执行与评分，无人工校准。它能帮助定位失败，不是 holdout、持续可靠性或生产通过率。不要改写原输出、评分和版本哈希使其“匹配”新版。

## 长任务 harness

| 操作 | 恢复/保留的对象 | 不能替代什么 |
|---|---|---|
| context reset | 新模型上下文，从外部工件重建 | 事务执行记录与当前授权 |
| compaction | 当前上下文的有损摘要 | 不丢关键证据的保证 |
| 进程恢复 | checkpoint、任务状态、已发生/未知效果 | 外部接口的业务幂等协议 |

先固定验收契约，再由执行者提交产物和证据，独立角色/上下文 evaluator 按契约核验外部状态。执行者不能改期望给自己判成功；独立角色不要求不同模型，也不自动消除裁判偏差。交接工件带版本、来源、成立条件、未知状态、效果键、下一步和授权引用；过期授权必须重验，不能照抄旧同意。

reset、分阶段 sprint、独立 evaluator 的粒度要按任务与模型的实际收益/成本选择。Anthropic 2026-03-24 案例本身随模型改变删减 reset 和 sprint，不把“三件套”当永久标准。

## 记忆分层与整理

以可追溯原始事件、选择性 notes、组织化 representations、实际 injected context 四种对象来定位缺口；这是组织与诊断视角，不要求所有信息按四步流水线处理。原始记录只证明当时记录了什么，不保证记录中的断言真实，更不是当前授权。

notes与索引/主题表示是派生物，带来源、作用域、版本、失效/覆盖关系。核对错误笔记时回到来源和必要的当前外部状态。删除/撤权要传播到派生笔记、表示、缓存、摘要及未来注入；原始记录也服从留存与删除，不为“真值”永久保存秘密。

Dreaming放进阶：交互间整理、纠错、提升既有记忆，不是第五层、意识或该文所讨论的权重训练。模型猜测不能静默升为事实或扩大权限；整理要可复核、版本化和回滚，再用独立任务验证收益。

## 诊断与回放安全

默认 trace 记录调用关系、版本、错误类型和组装清单等元数据，内容载荷默认关闭。只有符合授权与采集策略的受控快照才保存去敏内容；凭证不入日志，租户隔离、限权、采样和限留存不能因任务失败取消。引用/hash不等于正文，缺失内容时如实说明不能精确重建。

记录回放与重新调用模型区分。前者读取录下的工具响应，后者仍有随机性和环境变化；采样参数不保证同文输出。重放外部写操作使用桩或沙箱，不重新发信、扣款、发布；执行者自报读取路径不是完整独立工具轨迹。

## 单轮验证示例

以下仅用于组题，每轮只选一个；不同时要求列机制、写实现、解释结果。

- 评测：已经用保留集的一次失败修改了提示词，这批数据现在应如何归类？
- harness：执行者说“完成”，数据库状态仍是 queued，evaluator 应给什么结果？
- 记忆：笔记引用的原始事件已删除，下一次注入前应处理哪条派生关系？
- 回放：重新播放“发通知”步骤时，怎样让它不触达真实收件人？

模拟用例只能进入公共评测；当前用户的回答、档位与偏好仍按原 Skill 保存在本机私有目录。没有真实答题不生成掌握记录，没有运行不宣称实测。
