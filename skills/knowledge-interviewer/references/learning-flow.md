# 教材、图谱与陪练如何协作

Skill是学习入口和教学流程，references中的map决定范围与依赖，questions提供诊断题和评分判据，sources记录证据与版本边界。handbook保存完整案例与机制，materials保存图解与复习卡片。它们围绕同一个稳定知识点ID协作，不要求用户自己在目录间跳转。

## 每个知识点的流程

1. 诊断：读当前域map、本地最新缺口与questions对应点，只问一个可独立作答动作。不要把教材的答案提前发给用户。
2. 判断：依据机制与题目前提评价；用户质疑题面时先复验，不把题面错误记成不会。术语或某一种实现细节不是掌握的唯一证据。
3. 讲解：需要补课或用户主动要求学习时，定位并读取handbook对应节，结合sources核对版本。用教材解释当前缺口，不能只复述题库的A档关键词。
4. 验证：换一个未见过的最小场景，每轮只一个动作。刚听完能复述不等于延迟后独立迁移；用户要求换点或结束时停止追问。
5. 收尾：给对应教材入口；图解有助于展示依赖时才用materials，不能把整张总览当掌握证据。实际答题和复习安排只更新本地记录。

## 如何定位正文

在完整仓库根目录运行：

```sh
python3 skills/knowledge-interviewer/scripts/learning_content.py --domain frontend --point fe.ts.contract
```

输出公共教材文件及起止行、题库和来源路径，不读取个人档案。按输出读取对应节即可，避免一次加载整卷。适用于四个领域；serve和agent旧名可解析。多个正文匹配时以定义该ID的主节为起点，扩展实验仅在相关时补读。

引用入口时直接使用返回的heading和path/start_line，不把map的名称当作文件或章节标题，不凭印象估算行号。读取正文后保留限制条件，不能只摘第一句：尤其JMM是允许行为的规范模型，不要求每线程有物理私有副本。虚构教学数据要标假设，工具实际执行才可称实测。

普通学习者链接文案使用定位工具返回的display_title（去掉章节编号和内部ID），路径与行号保持真实。用户主动查看图谱或调试详情时才展示heading完整内部编号。

独立安装Skill而未携带handbook时，可以使用包内map/questions/sources继续陪练，但要说明完整案例教材未安装；不得声称读过不存在的教材。用户想要完整学习系统时应使用仓库版本。

## 个人偏好与公共规则

读取.local/learning/preferences中的output-style.md和interviewer-feedback.md（存在时）。前者是这位学习者的表达偏好，后者是历史教学反馈；两者都不是领域知识、成绩或其他学习者的默认背景。当前用户明确要求优先，偏好不能改变事实、伪造掌握或触发外部同步。

根目录同名旧文件只是历史副本，不作为新的权威输入；已有本地preferences继续使用，不自动覆盖或删除。PRIVACY.md是公共存储与发布契约，Skill执行其中的本地边界，脚本和Git检查负责部分技术防护。

初次保存必须通过learning_state.py：仓库模式检查忽略与跟踪状态，独立安装使用显式--standalone并放Git工作区之外；任何失败都停止保存并报告，不以手写模板替代检查。收尾仅总结实际观察，复习计划使用同一机制的新变体，避免只读轮与写入轮承诺不同。

权限拒绝后不自动chmod任何既有根目录、领域目录、sessions或档案文件，也不另选路径偷偷落盘；等待所有者明确授权补救后再验证。脚本会创建新的0700 sessions目录，新建会话文件须按0600创建。既有权限保持原样，无法满足则如实未保存。

原题或历史字段未提供就写未提供/未知，不把图谱、题库首题或自造题面伪装成已发生的会话；已有记录亦不可据此覆盖。知识点与真实答法可照实保存，不确定性同时保留。
