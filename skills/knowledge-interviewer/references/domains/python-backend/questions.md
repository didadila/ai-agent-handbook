## 使用规则

- 默认 Python 3.11+；纯 Python CPU 场景明确为常规启用 GIL 的 CPython。SQL 场景分别标 SQLite 或 PostgreSQL 17，不互相外推。
- 每轮只取首题、一个追问或最小验证之一，等回答再继续；下面的 A 档/错答不随题发送。追问按缺口选择，数量不是必须问完的配额。
- 首题答对输出不等于掌握；A 需要机制、条件与失败边界的独立证据。刚听完后同轮复述不记掌握；最小验证先确认接住，再在后续未见变体上确认迁移。
- “不会”或当天累计两次 C/D 就补课；题面/术语不明先作废澄清，不记用户错误。所有数字与事故窗口均为构造题面，不是实测统计。
- 首诊按语言 → 并发 → 任务，依赖未确认就停在前置；不要把全部题链变成问卷。已有用户复习命中最近机制缺口，不机械重发首题。
- 所有实验默认本地/模拟、标准库可完成；此文件没有安装、部署、云同步或真实写工具的默认授权。

## 语言

### `py.lang.objects`

**首题**：执行下面代码，只写出最后打印的值。

```python
a = {"items": []}
b = a.copy()
b["items"].append("x")
print(a["items"])
```

**逐轮追问**：
1. 解释 a 和 b 为何仍会共享 items。
2. 只改写 b 的赋值语句，使这次列表追加不影响 a。
3. 对 `t = ([],); t[0].append(1)`，只判断追加是否成功。

**A 档要点**：赋值绑定对象，copy 只复制外层；嵌套列表身份共享；复制需要更新的路径可隔离这次修改，不声称任意深层均隔离；tuple 固定直接引用，不冻结所指对象；is 比身份，== 比值。

**错误答法**：“字典复制就是深拷贝”“tuple 内部都不可变”“is 相当于业务相等”。

**最小验证**：`x = [1]; y = x; y = [2]`，只写出 x 的值。

### `py.lang.collections`

**首题**：`it = iter([1, 2]); list(it); print(list(it))`，只写出打印结果。

**逐轮追问**：
1. 解释第二次 list 没有再次读取原列表的原因。
2. 对 `{([1],): "x"}`，只判断构造字典是否成功。
3. 一个生成器在 with 打开的文件内 yield 后暂停，只判断它是否可能仍持有文件资源。

**A 档要点**：容器可创建新迭代器，迭代器本身有消费状态；StopIteration 后持续耗尽；键必须可哈希，tuple 含 list 仍不可哈希；生成器按需产出但可持有局部变量/资源；选择 list/dict/set 要考虑顺序、查找与身份，不依赖 set 插入顺序。

**错误答法**：“迭代器会自动重置”“所有 tuple 都可哈希”“生成器不会保留资源”。

**最小验证**：`items = [3, 4]; first = list(iter(items)); second = list(iter(items))`，只写出 second 的值。

### `py.lang.functions`

**首题**：执行下面代码，只写出打印结果。

```python
def add(x, items=[]):
    items.append(x)
    return items
add(1)
print(add(2))
```

**逐轮追问**：
1. 解释两次调用的默认 items 为何是同一对象。
2. 只改写该函数，消除未传 items 时的调用间共享。
3. `fs = [lambda: i for i in range(3)]` 创建结束后，只写出 `[f() for f in fs]` 的结果。

**A 档要点**：默认表达式在函数定义时求值一次；None/独立哨兵后在调用内新建容器，不用 `items or []` 丢弃调用方传入的空列表；闭包读取绑定不统一冻结值，可用默认参数显式捕获当前值；关键字专用参数可约束调用契约。

**错误答法**：“每次调用默认值重新求值”“所有 lambda 自动复制变量”“用类型注解避免共享”。

**最小验证**：`def f(x, *, limit=2): return x[:limit]`，只判断 `f([1, 2, 3], 1)` 是否是合法调用。

### `py.lang.types`

**首题**：`def echo(x: int) -> int: return x`，只判断 `echo("7")` 是否仅因注解就在运行时抛错。

**逐轮追问**：
1. 只指出拒绝不合法外部输入应放在哪个边界。
2. 工具参数 schema 合法但目标文档属于别的租户，只判断能否执行该读取。
3. 两个类不继承同一基类却实现同一 Protocol 的成员，只判断静态结构化类型检查是否可以接受它们。

**A 档要点**：Python 注解不由运行时强制执行；静态检查与显式运行时校验分工；转换/严格模式需核对所选校验库版本；schema 只约束结构，不证明授权、事实或业务状态；Protocol 支持结构化契约，不代替外部输入校验。

**错误答法**：“写 int 就自动转成整数”“Pydantic 通过就能扣款”“Protocol 自动拦截 HTTP 参数”。

**最小验证**：`value: int = "bad"`，只判断这行赋值是否由 Python 类型注解自动阻止。

### `py.lang.resources`

**首题**：Python 3.11 中先执行 `con = sqlite3.connect(":memory:")`，随后正常退出 `with con` 代码块，只判断 con 是否因此自动关闭。

**逐轮追问**：
1. 只指出异常路径上确保关闭文件的一个结构。
2. 捕获数据库异常后返回“写入成功”，只指出这个答复损坏的契约。
3. 解释垃圾回收为何不能作为及时释放外部资源的保证。

**A 档要点**：资源有明确所有者/作用域；with 协议按类型契约工作，sqlite Connection 上下文管理提交/回滚但不 close；需要 finally/closing 或显式关闭；异常清理后传播或映射已定义错误，不能冒充成功；不依赖 CPython 引用计数即时终结。

**错误答法**：“所有 with 都自动 close”“except Exception 吞掉更稳”“局部变量离开就保证文件关闭”。

**最小验证**：文件在 `with open(...) as f` 内读取时报错并退出该 with，只判断 f 是否会被该上下文关闭。

### `py.lang.environment`

**首题**：终端已激活 venv，但任务启动命令硬编码 `/usr/bin/python3`，只指出该任务实际选取解释器的依据。

**逐轮追问**：
1. 只指定本地检查当前解释器路径的一个 Python 表达式。
2. 把开发机 venv 整目录搬到不同绝对路径，只判断它是否是可靠的环境交付方案。
3. 数据库密码需要因环境而变化，只指定它是否应硬编码进公共题库。

**A 档要点**：解释器实际路径比 shell 激活状态可靠，sys.executable 可观测；venv 默认隔离 Python 包，不锁系统库、解释器版本或云权限；依赖版本与环境声明支持重建，不搬 venv；配置与秘密分离并脱敏；未授权不安装依赖。

**错误答法**：“激活一次所有子进程都强制用 venv”“venv 就是完整容器”“提交密码最可复现”。

**最小验证**：直接运行 `/path/to/venv/bin/python app.py`，只判断是否必须先执行 activate。

## 并发

### `py.async.eventloop`

**首题**：同一事件循环线程里，一个 async 函数执行 `time.sleep(2)`；此时已有另一就绪协程，只判断它能否在这两秒内由该线程继续执行。

**逐轮追问**：
1. 解释 async def 为何没有让 time.sleep 自动变成异步等待。
2. 定义 `async def f(): return 1` 后，在函数外执行 `coro = f()`，尚未 await 或调度，只判断 f 的函数体是否已执行。
3. 在 Python 3.11 的 TaskGroup 作用域正常退出时，只判断退出是否等待组内任务完成。

**A 档要点**：事件循环一次执行一个任务，切换需要实际挂起；协程调用得到对象，不自动执行；await 已完成对象/不挂起协程不保证让出；TaskGroup 约束子任务生命周期；async 提升等待阶段的并发，不提供纯 Python CPU 并行。

**错误答法**：“async def 总在后台”“所有 await 都切线程”“加 async 就能用满多核”。

**最小验证**：上述 time.sleep 改为 `await asyncio.sleep(2)`，只判断等待期间该循环能否运行其他就绪任务。

### `py.async.cancellation`

**首题**：await asyncio.to_thread 调用一个已开始的同步退款函数；等待它的 Task 超时取消，只判断能否据此保证退款未发生。

**逐轮追问**：
1. 只指出协程收到取消后放置资源清理的结构。
2. Python 3.11 TaskGroup 的一个任务抛 ValueError，只指出其他尚未完成任务会收到的操作。
3. 解释吞掉 CancelledError 为何会破坏结构化并发的预期。

**A 档要点**：取消是协作请求，在可取消的挂起点传播；CancelledError 继承 BaseException，清理后通常重新传播；timeout 使用取消并在上下文外表现为 TimeoutError；TaskGroup 非取消失败会取消兄弟任务并等待处理；取消等待不能杀掉已运行线程、撤回远端已提交副作用，未知结果需查询/幂等。

**错误答法**：“超时后线程被杀”“finally 会撤回邮件”“except BaseException 后继续跑更稳定”。

**最小验证**：远端日志确认已经完成写入，客户端随后取消，只判断这次取消是否撤销该写入。

### `py.async.backpressure`

**首题**：构造场景：worker 稳定每秒处理 10 件，入口每秒产生 100 件并存入无界队列，只判断积压是否会持续增长。

**逐轮追问**：
1. Queue(maxsize=20) 已满时，只指出 await put 的行为。
2. 已创建一百万个 Task 且每个在 Semaphore(10) 上等待，只判断信号量是否同时限制了待处理 Task 总数。
3. API 不允许等待超过既定预算，入口队列已满，只提出一种明确的满载策略。

**A 档要点**：同时限制入口、队列长度、执行并发与下游连接；有界 Queue 满时 put 等待，put_nowait 抛 QueueFull，maxsize<=0 为无界；信号量不消除已创建 Task；拒绝/限时等待/降级需按接口契约选择；内存 join/task_done 不是持久确认。

**错误答法**：“Queue(0) 不存东西”“只加 Semaphore 就不会积压”“队列无限大最不丢任务”。

**最小验证**：`q = asyncio.Queue(maxsize=1); q.put_nowait("a")` 后再 `q.put_nowait("b")`，只指出第二次操作的结果。

### `py.async.execution`

**首题**：常规启用 GIL 的 CPython 3.11 中，一段长时间的纯 Python CPU 循环改写成 async def，只判断它是否因此获得多核并行。

**逐轮追问**：
1. 只选择一个避免同步网络库阻塞事件循环的执行位置。
2. FastAPI 的 async 路由直接调用普通 def 工具函数，只判断该工具是否自动进入 FastAPI 线程池。
3. 只判断 free-threaded CPython 构建是否是 Python 3.11 默认能力。

**A 档要点**：异步不等于 CPU 并行；阻塞 I/O 可线程卸载，但取消等待不杀运行线程；CPU 密集优先考虑进程/释放 GIL 的原生扩展并实际测量；FastAPI 管理的普通 def 路由/依赖在线程池，直接普通调用不自动卸载；3.13 起 free-threaded 可选，扩展或启动配置可启用 GIL；无论 GIL 情况都不依赖复合操作天然原子。

**错误答法**：“所有 Python 永远只有同一种 GIL”“线程绝不可能 CPU 并行”“移除 GIL 后共享 Session 就安全”。

**最小验证**：线程执行释放 GIL 的原生计算库，只判断能否把“纯 Python 循环不能多核并行”的限定直接套给它。

## 服务

### `py.svc.contract`

**首题**：请求 JSON 类型完全合法，目标记录 tenant_id 与登录租户不符，只判断接口是否应返回该记录。

**逐轮追问**：
1. 只指出服务端对象授权检查应依赖的身份来源。
2. 接口返回 202 和 task_id，只判断这能否表示任务已经完成。
3. 内部数据库异常含连接密码，只指定能否把原始异常文本直接返回客户端。

**A 档要点**：结构校验和服务端认证/授权分开；信任认证上下文，不信任任意客户端 tenant_id；任务受理与完成状态分开；错误格式/状态需明确且不泄漏秘密；schema 转换模式需显式选择；类型合法不证明 SQL 安全或业务状态。

**错误答法**：“用户传 tenant_id 就能查”“JSON 合法即有权限”“全部返回 200 让客户端猜”。

**最小验证**：请求把 tenant_id 改成他人租户，只指出应以请求字段还是服务端认证上下文决定权限。

### `py.svc.lifecycle`

**首题**：FastAPI app.lifespan 内只创建一个 AsyncSession 并供所有请求并发使用，只判断这个会话共享方案是否安全。

**逐轮追问**：
1. 只指定可在应用生命周期复用的数据库资源类别。
2. Python 服务正常关闭且仍有在途数据库请求，只指出应先等待请求还是先关闭数据库资源。
3. BackgroundTasks 任务尚未执行时进程退出，只判断这个 API 是否承诺重启后恢复任务。

**A 档要点**：lifespan 管启动前获取、退出时释放；engine/池可应用级管理，Session 有事务状态，Session per thread、AsyncSession per task；请求/任务内部上下文管理会话；关闭按停止接入→有限等待/取消清理→关依赖；BackgroundTasks 是响应后同进程执行，不承诺持久交付；lifespan 是每个进程而非整个集群只一次。

**错误答法**：“异步会话只有一个连接所以可共享”“lifespan 自动跨进程单例”“响应后任务天然可靠”。

**最小验证**：两个并发 asyncio Task 各有独立事务，只指出应分配一个共享 AsyncSession 还是每个 Task 独立 Session。

### `py.svc.idempotency`

**首题**：同一租户同一幂等键已记录载荷“金额 10”，重试载荷改为“金额 100”，只判断它能否按原请求直接重放成功结果。

**逐轮追问**：
1. 只指出能识别这种 key 复用冲突的持久字段。
2. 两个并发请求都先查到“键不存在”，只指出数据库需要的防重复约束。
3. 下游写入已超时但结果未知，只提出一个安全的后续动作。

**A 档要点**：键标识业务意图，指纹绑定规范化关键载荷与版本；在租户/动作范围建立唯一约束，原子保存状态及结果；同键不同指纹拒绝冲突，同键处理中按契约等待/返回处理中；超时不是失败证据，外部效果需下游幂等或查询/对账；保留期限要覆盖重试窗口。

**错误答法**：“只比较 key”“先查再插足够”“超时就换新键重试”。

**最小验证**：租户 A 和 B 使用同一文本键但作用域分别隔离，只判断是否应因文本相同直接复用 A 的结果给 B。

### `py.svc.streaming`

**首题**：Agent 只把输出 token 写入 SSE socket，进程崩溃后没有任何持久状态，只判断 SSE 是否足以恢复执行到原步骤。

**逐轮追问**：
1. 只指出服务端支持断线重放时应持久保存的事件身份信息。
2. 客户端断开 SSE，但后台写工具已提交，只判断断连是否撤回写入。
3. 构造场景：客户端持有事件 5，而日志已从事件 20 保留，只提出一种恢复响应策略。

**A 档要点**：SSE 定义 text/event-stream、id/Last-Event-ID，不定义应用 checkpoint；run+事件序号、保留窗口、快照与重放属应用契约；事件持久化与发送分离；断连不证明取消/回滚；重放需授权、去重和有界缓冲，状态权威在服务端；首段发送后不能假定任意错误都可改为普通 HTTP JSON。

**错误答法**：“浏览器重连会自动恢复 Python 栈”“socket flush 就是 commit”“重放时忽略租户”。

**最小验证**：同一 run 的事件 8 因重连再次到达，只判断是否应把它作为新的执行步骤再调用一次工具。

## 存储

### `py.data.model`

**首题**：业务规定“同租户同幂等键只允许一条请求记录”，只给出数据库应唯一约束的列组合。

**逐轮追问**：
1. SQLite 查询的文档标题来自用户输入，只指出应使用字符串拼接还是参数绑定。
2. 订单必须引用存在的用户，只指定适合表达该关系的一类数据库约束。
3. 旧版本服务仍运行时要新增必填列，只提出一个兼容的迁移阶段。

**A 档要点**：租户与业务键进入约束而不只靠代码检查；关系、外键和状态表达业务不变量；参数绑定处理值，动态表/列名另用允许列表；JSON 用于适合的扩展数据，不免除身份与约束；迁移按兼容窗口分阶段，后端仍做授权。

**错误答法**：“只 unique(key) 就能把结果跨租户共享”“参数化会验证所有权限”“JSON 无需迁移”。

**最小验证**：SQLite 中存在 UNIQUE(tenant_id, request_key)，只判断相同组合第二次插入是否可无条件成功。

### `py.data.transactions`

**首题**：事务中调用远端邮件服务已成功，随后数据库回滚，只判断数据库回滚是否撤回这封邮件。

**逐轮追问**：
1. PostgreSQL 17 默认 Read Committed 中，两次 SELECT 之间另一事务提交，只判断后一次是否可能看见新值。
2. PostgreSQL Serializable 事务报序列化失败，只指定应重试最后一条语句还是整个事务。
3. 原子修改余额与写入审计行，只指出应放一个事务还是各自独立提交。

**A 档要点**：数据库原子性限于其事务资源，不包含 HTTP、对象或邮件；缩短持锁时间，外部动作移出事务并设计 Outbox/幂等；PG Read Committed 按语句快照，不能与 SQLite 概括等同；序列化失败需重新开始事务且避免重复外部副作用；序列值不保证回滚无间隙。

**错误答法**：“事务包住就全球回滚”“RC 整个事务同一快照”“只重试报错 SQL 永远安全”。

**最小验证**：已创建 SQLite 表，在一个 `with con` 的活动事务里插入行后抛异常退出，只判断这次插入是否应被回滚。

### `py.data.indexes`

**首题**：PostgreSQL 17 中为一个查询加了索引，只判断优化器是否必然选择该索引。

**逐轮追问**：
1. 要比较估计行数与实际行数，只指定应看普通 EXPLAIN 还是 EXPLAIN ANALYZE。
2. 对 PG17 B-tree `(tenant_id, created_at)`，查询按租户等值并按时间范围过滤，只解释该列序对扫描范围的作用。
3. `EXPLAIN ANALYZE UPDATE ...` 在生产执行，只判断它是否实际修改数据。

**A 档要点**：按过滤/排序/数据分布选择索引，以实际计划、行数、loops 与 buffers 验证；PG17 B-tree 左侧等值和首个范围限制扫描，不泛化所有索引/版本；索引增加空间与写入成本；ANALYZE 真执行，写实验用隔离环境，不把回滚说成撤回外部副作用；SQLite QUERY PLAN 只验证本地计划。

**错误答法**：“不走索引就是数据库坏了”“cost 就是毫秒”“ANALYZE 是安全只读”。

**最小验证**：表只有极少行，顺序扫描成本更低，只判断选择顺序扫描是否必然表示索引无效。

### `py.data.cache`

**首题**：cache-aside 读者已从数据库读到旧值，在写者更新数据库并删缓存后才回填旧值，只判断缓存是否可能再次变旧。

**逐轮追问**：
1. 只指出 TTL 能限制陈旧持续时间还是保证读到最新值。
2. 锁 A 过期后 B 持有同键新 token，A 恢复，只指出 A 释放时必须比较的值。
3. Redis 不可用但数据库仍可服务，只提出一种不放大数据库压力的降级策略。

**A 档要点**：cache-aside 存在回填竞态，需按业务容忍度选择版本校验/失效策略；TTL/抖动、合并回源、有界负缓存等是设计选择；key 包含租户/版本；锁用唯一随机 token 与原子比较删除，不能 GET 后 DEL；token 防误删不是单调 fencing，TTL 不能停止旧持有者；数据库是权威。

**错误答法**：“删缓存就永远一致”“先 GET 再 DEL 无竞态”“Redis 锁保护任何外部付款”。

**最小验证**：锁保存 token=B，迟到的 A 用原子 compare-delete(A)，只判断是否应删除 B 的锁。

### `py.data.objects`

**首题**：S3 presigned PUT 指向已有对象的同一 key，只判断成功上传是否可能覆盖原对象。

**逐轮追问**：
1. 临时凭证先于 URL 指定到期时间失效，只指出 URL 是否仍可持续授权到指定时间。
2. 上传成功但内容校验尚未完成，只指定此时应标“已上传”还是“可检索”。
3. 签名 URL 进入共享日志，只指出持有它的人可能得到的权限形态。

**A 档要点**：对象字节与数据库元数据分别管理，状态区分待上传/已上传/验证/索引/可用；key 分租户与不可变版本/唯一命名，避免意外覆盖；presigned 是受签名者权限/凭证/到期约束的 bearer token，可重复用到到期，不是一次性授权；业务校验、扫描、ACL 与清理需应用另做；本地文件只替代字节存储，不证明 S3 集成。

**错误答法**：“签名 URL 永远只能用一次”“有签名就不用对象授权”“HTTP 上传成功即索引成功”。

**最小验证**：S3 URL 未到期且凭证仍有效，只判断第一次成功下载是否自动使它失效。

### `py.data.retrieval`

**首题**：检索先在全租户库取 top-k，再删除别的租户结果，只判断这种流程能否替代检索前租户授权过滤。

**逐轮追问**：
1. 只指出 tenant/ACL 条件应放在候选检索之前还是只在答案生成之后。
2. 文档更新后仍检索到旧 chunk，只指出需要绑定的来源版本字段。
3. 未安装 pgvector，只判断能否用租户隔离的确定性检索替身验证权限流程。

**A 档要点**：在授权范围内生成候选，top-k 后过滤会损害召回且已跨越隔离边界；所有检索路径、缓存与日志执行权限，不把后端近似索引内部预/后过滤混为全库应用层过滤；保留 chunk/document/embedding 版本与来源；删除/撤权传播，结果返回前再防过期授权；向量相似不证明事实，召回与回答分别评估；pgvector 为扩展。

**错误答法**：“模型看到后再忽略就安全”“向量结果没有权限问题”“相似度高就是正确”。

**最小验证**：A 的请求只允许 A 的文档，B 的文档相似度最高，只判断 B 是否可进入本请求的授权候选集。

## 任务分发

### `py.jobs.delivery`

**首题**：持久队列 worker 已提交业务效果，在确认消息前崩溃；队列随后重新交付，只判断业务代码是否可能再次执行。

**逐轮追问**：
1. 改成业务处理前就确认消息后崩溃，只指出可能丢失的工作。
2. Celery retry 沿用原 task-id，只判断这是否自动提供数据库业务去重。
3. Celery 启用 acks_late 后执行子进程异常退出，只判断该选项本身是否保证一定重投。

**A 档要点**：区分发布、持久受理、领取、效果提交、确认；至少一次允许重复，去重记录与受控效果原子提交；Celery 默认执行前 ack，acks_late 改为返回后但 worker 子进程退出仍有 ack 边界；task_reject_on_worker_lost 需评估循环风险；retry 同 id/队列不自动业务去重；实际交付还依赖 broker/持久化/配置，BackgroundTasks 与内存 Queue 不等价。

**错误答法**：“确认后不用看效果”“acks_late 就 exactly-once”“同 task-id 自带所有工具幂等”。

**最小验证**：消息被重投，但相同业务键的去重记录已与数据库效果同事务提交，只判断是否应再产生一次该数据库效果。

### `py.jobs.outbox`

**首题**：业务事务已提交，进程在随后发布消息前崩溃；没有 outbox 或对账机制，只判断这条消息是否可能永久缺失。

**逐轮追问**：
1. 只指出业务行与 outbox 行必须如何共享提交边界。
2. 发布成功后、标记 outbox 已发布前崩溃，只判断恢复发布是否可能重复。
3. outbox 已标已发布，只判断能否据此证明消费者完成外部副作用。

**A 档要点**：业务与事件意图同库同事务消除“业务提交但事件意图丢失”；relay 独立重试发布，不能先标记再发；发布/标记窗口仍可重复，消费者按事件身份去重；维护积压、重试与对账；Outbox 不是 exactly-once，不自动把外部系统纳入事务。

**错误答法**：“两段 SQL 各自提交也一样”“Outbox 只有一次发布”“标已发布等于邮件已发”。

**最小验证**：事件 E 因 relay 重启再次到达消费者，只判断消费者是否应仅因再次收到就重复执行效果。

### `py.jobs.leases`

**首题**：worker A 租约已过期，B 用更高 generation 接管并写入结果；A 恢复后尝试提交旧结果，只指出结果写入端必须检查的租约身份条件。

**逐轮追问**：
1. 只判断 TTL 到期是否会物理终止 A 的线程。
2. 随机 Redis 解锁 token，只判断它是否天然等同于单调 fencing generation。
3. 邮件供应商不接受 fencing 或幂等键，只判断数据库 fencing 能否保证邮件绝不重复。

**A 档要点**：原子条件领取、持久 owner/generation、心跳与有界租约；接管递增 generation，结果/续租用条件写并拒绝旧身份，受保护资源必须执行 fencing 检查；随机 token 解决误删，单调 fencing 解决迟到写；过期不杀旧 worker；检查后外部调用仍有竞态，供应商不支持时需未知结果/对账/人工，不声称 exactly-once。

**错误答法**：“TTL 到就没有旧进程”“worker 自己检查一下就永久安全”“本地拒绝结果会撤回付款”。

**最小验证**：当前 generation=9，迟到 worker 以 generation=8 条件更新结果，只判断受保护写入应接受还是拒绝。

### `py.jobs.scheduling`

**首题**：任务只在内存执行 `await asyncio.sleep(3600)` 等待到期，中途进程崩溃，只判断重启能否从这个 sleep 自动恢复调度。

**逐轮追问**：
1. 只指出重启后仍需保存的执行时间字段。
2. 工具明确返回“不具备权限”，只判断它是否应无限自动重试。
3. 定时任务同一周期被两台调度器创建，只指出可用于去重的周期身份。

**A 档要点**：due_at/attempt/status 持久化，使用明确时区与时钟假设；并发调度原子领取；瞬时故障退避+抖动+次数/截止上限，永久错误终止/死信；计划 ID+周期时间形成身份，错过周期的补跑/跳过需业务决定；死信重放重新授权并保持幂等，不 sleep 代替持久状态。

**错误答法**：“重启会接着 sleep”“所有异常都是瞬时错误”“死信全量重跑不需要审查”。

**最小验证**：数据库保存任务 due_at 已过去且任务仍为待执行，只判断重启调度器是否可以据持久状态重新领取。

## Agent

### `py.agent.tools`

**首题**：模型产生合法的 `delete_document` 参数，但服务端未取得写入授权，只判断工具运行时是否可以直接执行。

**逐轮追问**：
1. 只指出工具执行授权判断的责任方。
2. 只读查询工具的结果含个人成绩，只判断是否可据“只读”标签自动上传到云知识库。
3. 模型不断重试失败工具，只提出一个运行时应强制的预算上限。

**A 档要点**：SDK 无关的输入/输出契约；服务端身份与授权、路径/对象范围、参数校验和允许列表；只读默认不授予外部同步权限；写工具审批绑定实际载荷/指纹，超时/步数/成本限制；结果结构区分成功/失败/未知，秘密脱敏；schema 与模型建议不授权、不证明效果。

**错误答法**：“模型说需要就执行”“只读所以任何外传安全”“Pydantic 通过就是审批”。

**最小验证**：默认只读 Agent 收到“安装依赖并部署”的模型工具建议，只判断是否已有执行该建议的授权。

### `py.agent.runtime`

**首题**：Agent 向远端提交写动作后崩溃，未保存返回结果；恢复时远端效果未知，只判断运行时能否无条件再次提交该动作。

**逐轮追问**：
1. 只指出恢复前应查询或核对的外部动作身份。
2. 用户批准了工具载荷 X，执行前模型改成载荷 Y，只判断原审批是否仍有效。
3. 只有 SSE token 文本而没有持久 step 状态，只判断它是否构成执行 checkpoint。

**A 档要点**：持久 run/step/工具意图、幂等身份、结果和状态转换；租约 fencing 防止旧 worker 覆盖受保护状态；未知外部效果先查询/对账，不能按未保存结果推定未执行；审批持久且绑定用户/工具/载荷/版本，变更需新审批；checkpoint 是应用定义恢复边界，事件流只投影；进程内历史不保证崩溃恢复。

**错误答法**：“结果没存就是工具没执行”“恢复 Python 栈就能 exactly-once”“审批一次永久授权”。

**最小验证**：旧 worker 持 generation=4，新 worker 接管为 5，只判断旧 worker 是否还能提交该 run 的受保护 checkpoint。

**进阶变体（每轮只取一个）**：新模型上下文从JSON工件接手，执行者自报done但JobStore仍是queued，只判断独立验收是否可通过。

### `py.agent.evaluation`

**首题**：一次 Agent 回答很流畅，但未检查工具结果和权限，只判断这是否足以证明任务成功。

**逐轮追问**：
1. 要区分检索错误与生成错误，只选择应单独验证的一层。
2. 要验证“外部效果已提交但结果未落库”的恢复，只指定一个应注入的崩溃位置。
3. 只读评估夹具换成真实付费云写工具，只判断原测试授权是否自动涵盖它。

**A 档要点**：固定模拟数据/预期与版本，区分检索召回、工具契约、状态恢复、最终效果；指标含成功、拒绝越权、重复效果、延迟/成本；故障窗口可重复注入，避免睡眠竞态；模拟 unittest 不证明生产集成；LLM 评分辅助而非唯一事实；同轮复述不是学习迁移证据，真实外部动作另授权。

**进阶变体（每轮只取一个）**：SDK封装改变了工具集和重试策略，只判断CLI评测的通过率是否可原样迁移。

**判档补充**：先对齐环境/身份/权限/调用契约；开发回归与未调优检验分开，固定验收不由执行者改期望。记录回放从桩读取，不执行真实副作用。进阶变体不成为五天必学配额。

**错误答法**：“模型自己说完成就算”“一个总体分数能定位所有问题”“测试可绕过审批”。

**最小验证**：同一任务返回正确文字但数据库出现两次扣款，只判断该用例应记为成功还是失败。

## 运维

### `py.ops.observability`

**首题**：处理耗时平均值稳定，但待处理队列持续变老，只指出需要补看的一个积压指标。

**逐轮追问**：
1. 一个请求触发持久任务后跨 worker 执行，只指定应传播的一个关联身份。
2. 结构化日志含完整 presigned URL，只判断是否应原样长期保存。
3. 只有总体 500 次数却无法区分超时/权限/冲突，只提出一个日志分类字段。

**A 档要点**：request_id/run_id/task_id/attempt/tenant 串联，指标与日志/trace 分工；看队列深度/最老年龄、p95/p99、池等待、重试和未知结果；分类错误并避免多层重复打印；URL token、密码、prompt/个人记录按最小披露；高基数标识放日志/trace，不无限作为指标标签。

**错误答法**：“均值正常就是健康”“日志越全越好”“所有请求 ID 作 metric label”。

**最小验证**：日志需要定位同一 run 的多次重试，只指出 run_id 是否应在重试时保持关联。

### `py.ops.deployment`

**首题**：构造场景：API 有 4 副本，每副本数据库池上限 20，数据库给该服务连接预算 60，假设每进程独立池；只判断这个配置是否超出预算。

**逐轮追问**：
1. worker 也访问同一数据库，只判断它的连接是否应计入上述总预算。
2. 服务正常停机仍有在途请求，只指出应先摘除 readiness 还是先销毁数据库池。
3. 要升级服务但未得到部署授权，只判断本地测试通过是否足以允许自动上线。

**A 档要点**：计算所有 API/worker 进程池与管理连接预算，池大小不是吞吐承诺；API/worker 分开扩缩并限制排队；readiness 停接入、有限 drain/取消清理、依赖关闭；lifespan 按进程运行；声明解释器/依赖、秘密注入、兼容迁移和回滚窗口；上线需显式授权，本地实验不证明生产容量。

**错误答法**：“每副本没超过60就没问题”“加进程不会增加连接”“测试过就自动部署”。

**最小验证**：副本数加倍但每副本池配置不变，只判断理论最大数据库连接数是否也加倍。

### `py.ops.recovery`

**首题**：系统每日生成备份文件但从未实际还原，只判断是否已经证明可恢复。

**逐轮追问**：
1. 只解释 RPO 衡量的恢复边界。
2. 数据库还原到旧时间点但对象/索引仍为新版本，只指出一种需要对账的版本关系。
3. 恢复后发现任务效果可能已在外部发生，只判断是否可直接全量重跑。

**A 档要点**：RPO 是可接受数据丢失窗口，RTO 是恢复服务时间目标；备份需验证还原、权限/密钥、校验与流程；数据库、对象版本和派生检索索引需对齐或重建；Outbox/任务重放保留幂等身份与 fencing，未知副作用对账；演练记录实际环境与用时，不说重启即恢复或备份即可用。

**错误答法**：“备份成功等于还原成功”“RPO 就是启动用时”“恢复后把所有写工具再跑一遍”。

**最小验证**：数据库恢复丢失去重记录，但供应商账单显示已付款，只判断该付款任务能否因本地查不到记录而立即重付。

### `py.eng.dependencies`

**首题**：同一份 `pyproject.toml` 今天和下周安装出不同的传递依赖版本，只指出应先补哪类记录。
