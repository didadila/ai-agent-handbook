## 浏览器与语言基础

### `fe.web.semantic` 原生动作控件

**首题**：停止按钮写成 `<div onclick="stop()">停止</div>`，鼠标能点，键盘按 Tab 找不到。只指定你先修改的元素。

**追问链**：① 换成原生控件后，哪些交互保证由浏览器提供？② 为什么单加 role 还不够？③ 卡片内链接点击会触发父卡片动作，哪个事件边界需要调整？各轮只取一个动作。

**A 档要点**：原生 button 提供动作语义、聚焦与键盘行为；表单中明确 type；role 不实现行为；区分 target/currentTarget 并定义嵌套动作传播策略。

**错误答法识别**：“加 CSS”“加 role 就完了”没有补齐键盘契约。

**最小验证**：表单中的“停止”不是提交动作，只填写它的 type 值。

### `fe.css.layout` 长内容撑破中间列

**首题**：两列 Grid，右列放一行无空格工具日志后页面横向溢出。右列已写 width:100%。只指出应先检查的一个尺寸约束。

**追问链**：① 自动最小尺寸如何影响收缩？② 代码块应在哪层滚动？③ 放大后输入框是否仍可达应在哪种视口下验？

**A 档要点**：检查 min-width/轨道最小值，允许内容列收缩；长代码在自身容器滚动；区分 content-box/border-box 与 computed styles；不能靠裁切藏住不可达内容。

**错误答法识别**：“换成 Flex”“全局 overflow:hidden”没有说明内容最小尺寸。

**最小验证**：一个 Flex 子项允许小于内容宽度，只填写常用的 min-width 值。

### `fe.web.rendering` 很快的网络与卡住的输入

**首题**：每 token 到达都写 DOM、读 offsetHeight，再写滚动位置；性能轨迹出现反复 Layout。只指出一个应先消除的操作模式。

**追问链**：① 读几何为何可能迫使同步布局？② rAF 内运行长计算为什么仍会卡？③ 网络耗时无法覆盖哪段用户等待？

**A 档要点**：写后读几何可能强制布局，交错循环放大成本；集中读写；rAF 不消除计算；用户看到变化还依赖样式/布局/绘制。

**错误答法识别**：“换更快模型”“包一层 rAF”没有解释轨迹里的 Layout。

**最小验证**：rAF 回调里持续计算 500ms，只判断期间输入能否及时被该主线程处理。

### `fe.js.value` 浅拷贝的历史记录

**首题**：`a={m:{text:'旧'}}; b={...a}; b.m.text='新'`。只写出 a.m.text 的值。

**追问链**：① 哪一级身份仍相同？② 只改写一个隔离嵌套更新的表达式。③ const 为什么不阻止这次变化？

**A 档要点**：展开仅一层，a.m===b.m；更新沿路径复制；const 限制绑定重新赋值；JSON 克隆并非任意对象的无损方案。

**错误答法识别**：“spread 是拷贝所以不变”“const 深层不可改”。

**最小验证**：`b={...a,m:{...a.m}}` 后修改 b.m.text，只判断 a.m 是否仍被共享。

### `fe.js.scope` 回调捕获的绑定

**首题**：`jobs=[]; for(var i=0;i<3;i++) jobs.push(()=>i)`，循环后执行 `jobs.map(f=>f())`。只写返回数组。

**追问链**：① 三个函数共享几个 i 绑定？② 换 let 后绑定为何不同？③ 普通方法直接作为回调传递时，this 由什么决定？

**A 档要点**：var 共用绑定最终为3；let 每轮独立；闭包保留词法环境不是统一冻结所有值；普通函数 this 看调用方式，箭头函数沿用外层。

**错误答法识别**：“函数建立时复制了 i”“异步回调天然拿最新值”。

**最小验证**：本题 var 改 let，只写新的返回数组。

### `fe.js.async` 超时没有撤销工作

**首题**：退款请求与 100ms timer 做 Promise.race，timer 先拒绝；500ms 时服务端提交退款。只判断外层拒绝能否证明退款未发生。

**追问链**：① race 控制的是哪一层结果？② AbortController 对已提交副作用能保证什么？③ 指定浏览器普通脚本后，单独给 sync/Promise/timer 代码预测顺序。

**A 档要点**：外层先 settled 不取消底层；取消需协作，服务端副作用可能完成；重试要幂等或查询未知结果；同步→微任务→后续 timer，timer 不保证准时。

**错误答法识别**：“reject 就回滚”“Promise.all 失败会取消全部请求”。

**最小验证**：只说出阻止重复退款应依赖前端 timer 还是服务端幂等。

### `fe.ts.contract` as 之后仍是坏数据

**首题**：网络 JSON 的 seq 是字符串，代码写 `JSON.parse(raw) as RunEvent`，编译通过。只指出缺失的入口步骤。

**追问链**：① unknown 与直接断言的边界差异是什么？② 用什么类型结构表达互斥事件？③ schema 通过为何不证明对象归属合法？

**A 档要点**：运行时校验字段/范围/版本；联合按 type 收窄并穷尽处理；静态断言不转换或验证数据；授权另检。

**错误答法识别**：“重新生成类型”“any 改成 RunEvent”仍无运行时检查。

**最小验证**：`seq=-1` 类型是 number，只判断仅查 typeof 能否通过业务范围检验。

## 状态与生命周期

### `fe.web.lifecycle` 旧请求覆盖新会话

**首题**：A 查询先发，切到 B 后 B 先返回，A 后返回覆盖页面。已配置输入防抖。只给出一个结果提交条件。

**追问链**：① 防抖改变的是哪个时刻？② abort 失败或回调已排队时谁拒绝旧提交？③ 卸载后哪些资源仍有所有者？

**A 档要点**：scope/会话+revision 匹配当前视图才能提交；切换推进版本并清理资源；abort 降浪费不替代提交复验；清理幂等且不误伤新连接。

**错误答法识别**：“延长 debounce”“总显示最后返回的结果”。

**最小验证**：当前 revision=5，返回结果携带4，只选择提交或丢弃。

### `fe.state.task` 掉线后的任务

**首题**：页面最后收到任务 running，随后断网。后台是否执行完没有证据。只写一个不冒充任务终态的展示状态。

**追问链**：① 为什么一个 isLoading 不够？② 快照 seq=40 后从哪里续流？③ 旧失败回滚为何不能整份覆盖新状态？

**A 档要点**：任务、连接、编辑分开；断线只丢观测；快照与游标配套，续流覆盖缺口；终态来自权威证据；乐观操作按ID确认/撤销。

**错误答法识别**：“断网就 failed”“不转圈就是 completed”。

**最小验证**：取消命令已发但未确认，只从 cancel_requested 与 cancelled 中选择一种。

### `fe.render.react` 订阅的旧快照

**首题**：text 初始为空，订阅建立后连续收到 A、B，回调执行 `setText(text + delta)`，两次都读初始 text。只改写该更新表达式。

**追问链**：① 回调的 text 来自哪次渲染？② 为什么列表下标 key 可能迁移草稿？③ 给定开发环境、根部启用Strict Mode，setup→cleanup→setup 后剩几条订阅才合理？④ hydration 首次不一致应检查什么输入？

**A 档要点**：累计 state 使用函数式更新；快照与稳定身份分开；Effect 清理对应资源，声明依赖；SSR/客户端首次输出一致；函数更新不自动解决跨 run 隔离。

**错误答法识别**：“空依赖就不会错”“关闭 Strict Mode”“随便随机 key”。

**最小验证**：连续追加 A、B 且采用函数更新，只写最终字符串。

## 网络、安全与系统能力

### `fe.web.http` resolve 的 403

**首题**：fetch 已 resolve，response.status 为403，代码直接解析并进入成功。只指定应先检查的响应条件。

**追问链**：① no-cors 为何不能给脚本读取权限？② CORS 为何不等于业务授权？③ no-cache 与 no-store 分别允许存储吗？各问单轮。

**A 档要点**：检查 HTTP 成功状态与内容类型再校验；CORS 管跨源读取、不能替代CSRF/授权；缓存私有性与新鲜度分开；副作用重试依契约。

**错误答法识别**：“等 catch”“允许所有 origin 就安全”。

**最小验证**：HTTP 500 的 fetch 正常返回 Response，只判断是否必然进入 catch。

### `fe.stream.recovery` 有缺口的续流

**首题**：本应用同一任务的 seq 从1连续递增，last_seq 是已完整应用的序号。当前 last_seq=8，收到 seq=10。只指定下一步动作。

**追问链**：① 为什么不能马上推进到10？② seq=8 重复与 seq=9 相同文字有什么差别？③ EOF（连接读完）为何不能当任务完成？④ 游标超出历史保留期如何恢复？

**A 档要点**：先补缺口或取带游标快照；按任务+序号去重不按文本；UTF-8与SSE帧跨chunk；校验后原子更新投影与游标；只认权威终态；应用序号假设要明确。

**错误答法识别**：“忽略9继续”“文字一样就丢”“EventSource 自动全包”。

**最小验证**：seq9 与 seq10 的 text 都是“好”，只写应得到几个“好”。

### `fe.security.output` 看似无脚本的链接

**首题**：Markdown 禁用了 script 标签，但允许任意链接协议。只指出还缺的一个输出检查。

**追问链**：① 为什么文本转义不能直接替代允许富文本时的清洗？② CSP 能否替代安全 DOM 入口？③ iframe 预览与父页面 postMessage 如何确定消息来源？

**A 档要点**：按文本/HTML/URL等上下文建立限制；最终DOM前清洗与URL allowlist；限制远程资源外发；iframe最小权限与origin/source校验；提示注入另有工具权限边界。

**错误答法识别**：“模型生成所以可信”“删 script 足够”。

**最小验证**：工具返回 HTML 放进 textContent，只判断其中标签是否应执行。

### `fe.a11y.status` 抢走用户阅读位置

**首题**：用户打开审批对话框并完成确认，对话框关闭。只指定焦点的合理返回目标。

**追问链**：① 模态内 Tab 应如何移动？② 为何每 token assertive 播报反而阻碍使用？③ 虚拟列表卸载焦点项会破坏什么？

**A 档要点**：通常回触发控件，若已移除则选符合后续流程的合理目标；语义控件与可见焦点；状态按阶段适度播报；浏览器自动化不等于真实读屏全验。

**错误答法识别**：“焦点放 body”“ARIA 越多越好”。

**最小验证**：普通“检索完成”不应抢焦点，只选择状态播报或强制聚焦。

### `fe.approval.scope` 批准了另一笔动作

**首题**：用户看到订单A退10元，确认前后端动作改成订单B退100元，旧 approval_id 仍被提交。只给出服务端应返回的处理结果。

**追问链**：① 批准记录应绑定哪些关键事实？② 前端算的摘要为什么不能独立授权？③ 双击防重与业务幂等分别在哪保证？④ 审批后对象状态变化要在哪复验？

**A 档要点**：拒绝旧批准并重新展示；可信端绑定动作/精确对象/参数/版本/期限/主体；执行前复验并保护状态转移；幂等避免重复效果，不依赖按钮禁用。

**错误答法识别**：“同类退款已经确认过”“前端哈希没变就能做”。

**最小验证**：金额从10变成100，其他字段相同，只判断旧授权是否仍有效。

### `fe.perf.streaming` 无界的增量积累

**首题**：token 到达即全量解析历史 Markdown，轨迹显示解析占据主线程。只指定第一个要缩小的工作单元。

**追问链**：① 合并更新为何要在结束时flush？② 把同样重活塞进rAF能否降低计算量？③ 缓冲满时哪些业务事件不能静默丢？④ 用户向上滚动后应怎样处理自动跟随？

**A 档要点**：限制重算范围、合并与分段、虚拟化的焦点代价；有界队列和明确恢复；tokens/s不等于交互延迟；按目标设备测轨迹。

**错误答法识别**：“加memo”“全部丢掉中间事件”“服务器更快即可”。

**最小验证**：用户已离开底部阅读旧引用，只选择强制滚底或保留位置。

### `fe.quality.delivery` 旧标签页的资源

**首题**：旧页面晚些时候动态导入旧chunk，新发布已删除该文件而产生404。只指定交付流程应保留的资源范围。

**追问链**：① 内容哈希资产与HTML缓存策略为何不同？② 有lock为何仍需固定工具链？③ 只回滚JS为何不保证旧审批接口可用？

**A 档要点**：保留兼容窗口内旧资产；入口可重新验证，哈希资产长期缓存；锁依赖且固定环境；新旧协议与数据迁移独立设计回退；浏览器配置不含秘密。

**错误答法识别**：“让用户清缓存”“有lock不用其他条件”。

**最小验证**：凭据作为构建环境变量进入bundle，只判断浏览器用户能否读取。

### `fe.eval.journey` 完成文字不是独立证据

**首题**：产品在意外EOF后错误显示“完成”；测试只查这两个字，测试通过。只写一条能抓住该错误的期望断言。

**追问链**：① 期望状态应从哪里来？② reducer绿能否证明真实按钮无遮挡？③ mock服务拒绝越权能否证明生产后端拒绝？④ flaky重试通过后要保留什么证据？

**A 档要点**：故障输入下无权威终态不能completed；期望独立于实现；按纯逻辑/协议/浏览器/服务端分层；确定性和随机系统分开验证。

**错误答法识别**：“改快照让它通过”“看最后截图就够”。

**最小验证**：网络断开且没有终态事件，只判断completed断言应通过还是失败。

### `fe.product.artifact` 旧保存响应覆盖新草稿

**首题**：草稿基于服务端v3保存，服务端已是v4。只选择一种既保护现有版本又不丢本地修改的处理结果。

**A 档要点**：拒绝冲突/保留dirty草稿并显式合并；上传和处理分阶段；引用document/version/位置；服务端验文件与权限；owner释放URL。
