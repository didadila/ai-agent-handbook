# 陪练展示协议 v3

当前用户明确要求优先，其次读取本地preferences。以下只约束默认补课与保存收尾，不约束用户主动要求的长报告，也不强迫普通出题套三段标题。

## 可判定的三段结构

默认补课必须从以下首个标题开始，整轮恰好这三个三级标题，顺序不得变化：

```markdown
### 结论
一句机制结论。

### 机制
|环节|说明|
|---|---|
|边界|一句必要说明；教材入口放在此表的一个单元格内|

### 验证
一个作答动作。
```

|段|允许内容|不允许内容|
|---|---|---|
|结论|一个物理行的一句话|开场旁白、人格/技能加载说明、另起段落|
|机制|一张1～4内容行的Markdown表，或一行最多4步的箭头链|散文段、第二张表、修法清单、独立教材入口|
|验证|一个物理行的作答动作；必要时其前仅放一个≤6行代码块|独立的“最后验证一下”导语、多个段落或第二题|

因此“代码+问题”属于验证段的两种允许元素，不按空行猜块数；表头不计内容行。教材链接只能放机制表格单元格或箭头链末步，不单独成段。不加与图表等价的段落。长代码、案例复盘与深度背景等用户要求“展开”再提供。

收尾/保存使用固定标题 `### 状态`、`### 记录`、`### 入口`：
状态只有一行实际保存结果；记录只有一张1～4内容行表格；入口只有一行真实链接或未保存原因。
不出题、不讲新机制、不新造历史记录。不保存时入口段可写“本轮未保存，无新记录入口”。

## 准确性适用于每种题型

- route、wrong、boundary、skip、format、privacy都遵守事实和证据规则。skip不能借换点使用未标注的伪实测数字。
- 原创数字场景在第一次使用前写“假设/构造案例”；声称实测必须有实际运行记录、环境和样本，题库/教材的教学案例不能转述为真实事故。
- 内部ID、L1/L2/L3和评测元数据不在普通学习者回答中展示；改用知识点名称与必要技术术语。用户明确要看图谱/调试详情或打开本地记录时才展示ID。代码中的合法标识符不受此约束。
- 机制结论带足必要条件：例如数据竞争先确认同一位置的冲突访问和至少一个非同步操作，再判断happens-before；不能把“无锁”或“两个只读访问”单独当作充分条件。
- 权限门禁拒绝后不自动chmod既有目录/文件，也不手写模板规避。说明未保存，等待所有者明确授权处理；新建私有目录和新文件按0700/0600创建不属于修改既有权限。

维护者可用 `scripts/check_response_format.py --mode teach <回复文件>` 或 `--mode close`做结构粗检；它检查标题、段内元素、表格行数、代码行数和内部标识外露，不判断机制是否正确、数字是否真实或是否只有一个语义作答动作。这些仍由预声明rubric评审。

## 合成补课示例

### 结论
类型断言不会转换或校验运行时数据。

### 机制
|阶段|发生什么|
|---|---|
|编译期|as表达程序员的类型断言|
|运行期|断言被移除，原数据保持原值|
|输入边界|应用代码另行校验，并按需要显式转换|

### 验证
假设接口返回seq为字符串"10"，执行seq + 1得到什么？

上例不提前用于诊断题；补课后能复述不等于延迟后的独立掌握。用户要求结束时使用收尾结构，不追加验证。
