按你已有编程经验，范围定为 Python 后端的存储、任务分发和 Agent，目标是五天搭出一个本地教学原型，不是掌握完整生产架构。当前可用资料没有 Python 专属领域包，因此按无包回退规则临时组织路线，不套 Java/Go，也不要求先学它们。

临时知识路线：Python 对象与错误处理 → HTTP 服务边界 → 数据存储与事务 → 缓存边界 → 任务分发与重试 → Agent 工具循环 → 测试与可观测性。

| 天 | 重点 | 3 小时安排 | 计划产出 |
|---|---|---|---|
| 第 1 天 | Python 服务基础 | 45 分钟：对象引用、可变参数与异常；90 分钟：设计任务创建、任务查询两个 HTTP 接口；45 分钟：输入校验和错误响应测试 | 任务服务骨架，暂用内存存储 |
| 第 2 天 | 存储与一致性 | 45 分钟：SQL、主键、事务与索引的用途；90 分钟：用 SQLite 保存任务及状态；45 分钟：设计重启后查询与失败回滚的验证 | 持久化任务表；理解缓存不能替代可靠存储 |
| 第 3 天 | 任务分发 | 45 分钟：请求进程与 worker 的职责、排队和背压；90 分钟：用 Python queue 与线程模拟后台任务分发；45 分钟：设计队列满时的处理，比较 Redis 缓存与队列的不同职责 | 提交后返回任务标识，后台执行并更新状态；明确内存队列不支持跨进程且重启会丢失 |
| 第 4 天 | 任务可靠性 | 45 分钟：超时、有限重试、重复执行与幂等；90 分钟：围绕任务标识设计重复提交防护、失败状态和重试上限；45 分钟：设计故障注入测试，梳理真实消息队列的确认与重投递边界 | 可检查的失败处理流程；不把去重标识当成副作用绝不重复的保证 |
| 第 5 天 | Python Agent 闭环 | 45 分钟：模型提出工具调用、程序校验并执行、结果回传的循环；90 分钟：用固定模型响应模拟创建/查询任务工具，设步数上限并限制可用工具；45 分钟：设计正常完成、非法参数、工具失败三类端到端测试 | Agent → 工具 → 任务服务 → 存储的本地演示原型 |

每天的时间包含阅读、设计和动手，不额外叠加作业。Redis/Celery 等跨进程组件的实接、真实模型 API 和部署留到后续，避免五天内被环境搭建吞掉学习时间。

本轮仅提供计划，不开始提问、不判档；未运行代码、未读取个人档案、未写入学习状态，也未安装或部署。
