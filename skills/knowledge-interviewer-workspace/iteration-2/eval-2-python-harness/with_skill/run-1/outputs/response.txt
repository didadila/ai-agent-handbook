### 结论
不够：reset 和 compaction 管模型可见信息，持久运行时管崩溃恢复与副作用，是否完成要按预先固定的契约独立验收，不能凭一个 JSON 或执行者的 done。

### 机制
| 环节 | 机制与边界 |
|---|---|
| context reset | 开启新模型上下文，从外部工件重建任务信息；JSON 只是容器，应包含版本、来源、成立条件、未知状态、效果键、下一步与授权引用，旧授权需重验，不能拿摘要代替事务执行记录。 |
| compaction | 把当前历史压成有损摘要，减少上下文占用；不保证关键证据完整保留，也不恢复进程。完整案例教材未安装，本轮依据[包内工程参考](references/engineering-learning.md)补课。 |
| 进程恢复 | Python runner 从持久 run/step 状态与 checkpoint 接续，不是还原 Python 调用栈或旧数据库连接；外部效果未知时先按效果身份查询、对账，再决定重试，仍需业务幂等；接管需防旧 worker 覆盖受保护状态。 |
| 谁验收 | 任务开始前固定验收契约；执行者提交产物和证据，不能改预期给自己放行。独立角色/上下文的 evaluator 核对数据库、索引等外部状态与产物，而非只读 done；可用同一模型，但独立上下文不自动消除裁判偏差。 |

### 验证
假设固定验收要求指定文档版本已进入检索索引，执行者报告 done，但独立 evaluator 查到该版本尚未入索引：本次验收能通过吗？
