### 结论
不够：reset 和 compaction 管的是模型可见上下文，进程恢复靠持久任务状态，执行者的 done 不能替代独立验收。

### 机制
| 边界 | 机制 |
|---|---|
| Context reset | 清掉旧上下文，再按当前任务重建目标、约束、已验证结果与下一步；像换一张工作台，不会撤销已执行的动作。JSON 可以作交接载体，但必须有版本、状态与可核对的证据，不能只有一句摘要。 |
| Compaction | 用摘要或裁剪减少上下文占用，是有损整理，不是进程重启；须保留约束、已执行动作及结果，并能追溯原始事件，否则可能忘记限制或重复执行。 |
| Python 进程恢复 | 崩溃后不会自动恢复协程、连接或内存历史；从持久 run/step、工具意图、幂等身份、审批与结果重建资源并续跑。外部效果未知先对账，接管需防旧 worker 覆盖状态；摘要不等于 checkpoint。 |
| 谁验收 | 用户确定目标与验收标准，执行者交付结果和证据；Harness（模型外的任务控制代码）调用独立校验检查租户隔离、来源版本、预期检索结果及恢复状态，通过后才标完成，不能只信 done。完整教材未安装，本轮回退到[包内证据索引](references/domains/python-backend/sources.md)。 |

### 验证
假设 Python worker 崩溃后，只剩会话摘要，没有持久步骤状态：这份摘要足以保证任务可靠续跑吗？
