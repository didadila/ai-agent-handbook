# 学习系统的职责与下一步

## 一个入口，多种材料

学习者可以始终通过Skill学习，不需要自己翻目录。Skill负责选点、提问、诊断、讲解、验证和记录；教材是讲解时读取的内容，不是另一个必须人工进入的产品。原来只在Skill里链接教材首页，没有要求按ID读取正文，导致教材可能被绕过；现已在learning-flow中补齐此流程，用learning_content.py定位135个知识点的正文节。

|组成|负责什么|何时使用|
|---|---|---|
|Skill与通用references|教学流程、判档和交互边界|每场陪练|
|领域map/questions|范围、依赖、诊断题和评分判据|选点、出题与判断|
|领域sources|事实证据、版本和适用条件|讲解、争议和易变事实|
|handbook|完整案例、机制和取舍|补课、主动学习和深入解释|
|materials|依赖总览、图解和复习卡片|需要视觉导航或短复习时|
|evals与测试|检验教学行为与代码性质|系统维护时，不当成学习者成绩|
|.local/learning|当前学习者成绩、错题、偏好和会话|会话前后，仅本地|

题库可以概括教材判据，但不能复制整节变成第二份教材；版本事实以sources及官方资料为准。发现冲突先查证再修改，不能靠教材、题库和图解多数表决。

## 为什么有独立文件

- interviewer-feedback.md是个人对历史出题方式的反馈，不是公共出题规则全集。
- output-style.md是个人表达偏好，不是知识或成绩。
- 前两者放.local/learning/preferences，存在时由Skill读取。根目录同名历史副本只有确认逐字节一致后才清除，本地偏好正文不变。
- PRIVACY.md是整个仓库的公共存储和发布契约，读者、维护者、脚本和Skill都受其约束，保留根目录便于发现。Skill保留执行所需的隐私规则，脚本只防护部分可检查路径，不能把Git忽略等同于数据访问控制。

## 覆盖不等于完整

2026-11-10原24例两轮的23/24与24/24、定向修复初轮失败及复测均保留。全量复评指出的歧义已由v3处理：固定可检查三段、权限拒绝不自动chmod、全题型证据/准确性判据、隐藏内部标识、全局入口指向当前仓库。候选16例和全局入口2例分别满足预声明标准，详见[v3优化报告](reports/2026-11-10-v3-optimization.md)；不同标准、不同轮次不混算，单次样本仍不证明稳定性。

135点是当前核心课程，不是所有前后端与Agent知识的穷举。Java七章更接近逐点核心讲义，和Agent长案例章节的深度尚不完全相同；四域同目录契约不代表同等深度、实验覆盖或模型评测成熟度。

下一步按以下顺序补，不先追求更多题目：

1. **验证教学有效性**：24个合成行为用例已在2026-11-10跑两轮——首轮23例通过、`ai-agent-format`因补课单轮超出简短边界未通过；修复提交b8ec628后用同一批case原话与同一份rubric复跑，24例通过且无回归。实际输出、失败样本与判据外观察（首轮25条、复跑36条）分别保留在`evals/<域>/runs/2026-11-10/`与`runs/2026-11-10-v2/`，协议与限制见[行为评测报告](reports/2026-11-10-behavior-eval-run.md)和[修复后全量复评](reports/2026-11-10-recheck-after-fixes.md)。两轮都是每例单次采样，下一步补：同一用例多次采样以暴露轮间不一致（复跑已出现同一规则下「整轮三块」4/4与0/4相反、privacy对私有目录门禁两种相反处置）、把机制正确性与可机械计数的块数上限写成rubric判据（现行「短表格+不重复段落」判据检测不到开场旁白与教材入口独立成段）、题面数字必须标假设的判据化、强制真实读取教材正文并核对入口行号、题面缺陷与合理替代解释场景，以及仓库模式与`--standalone`两条初始化路径各自覆盖。评分保留实际输出和失败，不能只统计文件齐全。
2. **实验与迁移能力**：Go/Java补可运行实验和故障输入；前端补真实浏览器与服务端契约测试；Agent补端到端轨迹与硬门。把“会解释、会修改代码、会定位故障、延迟后会迁移”分开观察。
3. **证据粒度**：逐条绑定断言、具体段落、版本与核验日期。Java按主题挂一组链接的行仍需细化，尤其分布式ID、限流、缓存和数据库日志；论文或厂商实验数字不能泛化成永久定律。
4. **公共基础**：根据学习目标补OS/进程线程/内存与IO、TCP/DNS/TLS/HTTP、数据结构与复杂度、SQL建模与迁移、Linux诊断。现有卷涉及部分应用，没有系统覆盖这些前置，不宜假定新学习者已掌握。
5. **跨卷项目**：同一任务贯穿前端状态、后端权威状态、Agent副作用和持久化恢复。用超时未知结果、重复事件、权限撤销、版本冲突及重启恢复验证，避免四卷各会背却无法协作。
6. **工程维护**：依赖与运行时升级、供应链与第三方来源归属、备份恢复、CI发布回滚、容量和成本。当前有零散条目，后续应补明确目标和实操验收。

## 新鲜度不是只看日期

语言规范和稳定机制按目标版本学习，不因不是最新版本就删除。默认值、弃用项、浏览器支持、SDK和协议状态必须核对目标环境；定价与实时产品能力在使用时查询。历史实现保留用于理解旧系统，标清历史及迁移路径。只打开来源入口不等于核实该页支持全部关联断言。

本轮抽查不替代全库逐句认证：Agent趋势表已到例行核验日，除MCP抽查外其余仍是历史快照；其他三域也只对明确记录的切面复核，不批量刷新verified_at制造“新鲜”表象。
